## 結論

非対話セッションから Windows の R インストーラを起動すると、**CPU ほぼ0のまま何時間でも止まる**。原因はインストーラが manifest で管理者昇格を要求していて、UAC の確認ダイアログ（`consent.exe`）が画面で「はい」を待っていること。エージェント側からはクリックできない。

`/VERYSILENT` を付けても、インストール先を管理者権限の要らないユーザーディレクトリにしても回避できなかった。**昇格要求は manifest 側にあるので、引数やインストール先では消せない。**

## ハングの判定

54分間 CPU ほぼ0で、期待される成果物ファイルも書かれない → GUI 待ちと判断した。プロセスが生きていることは進行の証拠にならない。判定に使えたのは2つ。

- CPU 時間が増えていない
- 期待するファイル（`.../bin/x64/Rscript.exe`）が出現しない

3回試したところ、UAC ダイアログが3つ溜まっていた。ここまで来ると原因はほぼ確定する。**同じ操作を繰り返して「待ち」が積み上がるなら、それは処理待ちではなく応答待ち。**

## 進捗の判定を2回間違えた

- **exit 0 の false positive** — バックグラウンドの完了通知が「ユーザーディレクトリへのインストールが exit 0 で完了」と伝えてきたが、実際には入っていなかった。**exit code は「入ったか」の証拠にならない。** ファイルの存在で確かめる。
- **PATH の判定ミス** — 別セッションで「PATH に通っていない」と報告したが、これは誤りだった。`Rscript` は素で動く。紛らわしいのは `R` のほうで、PowerShell の組み込みエイリアス `r`（= `Invoke-History`）に食われて `Get-Command R` が Source が空のエイリアスを返す。PowerShell から対話 R を起動したいときだけ `R.exe` と拡張子付きで呼ぶ必要がある（`Rscript` は無関係）。

`Get-Command <名前>` の結果が「エイリアスだが Source が空」なら、それは組み込みエイリアスに食われているサインで、実体が無いことの証拠ではない。

結果として R 4.6.1 は `C:\Program Files\R\R-4.6.1` に入っていた。どの試行で完了したのかは特定できていない。**「入っていない」という判断を2回間違えたので、判定はコマンドの成否ではなくファイルの存在で行う。**

## パッケージ側は昇格なしで入る

言語ランタイム本体には昇格が要るが、**依存パッケージには要らない**。この切り分けで非対話でも大半が進む。

- ユーザーライブラリ（`R_LIBS_USER` の既定 `~/AppData/Local/R/win-library/4.6`）を作れば、管理者権限が要る `C:\Program Files\R\...\library` に触らずに済む
- `type="binary"` を固定して CRAN の Windows バイナリを入れれば、ソースビルド（Rtools）が不要になる

実測では6パッケージ + 推移的依存17個がエラーなし・exit 0 で入った（magrittr 2.0.5 / tibble 3.3.1 / dplyr 1.2.1 / stringi 1.8.7 / openssl 2.4.2 / philentropy 0.10.0）。

## 原因はパッケージ定義の側にあった

翌日、`winget show` でインストーラのメタデータを見たら、引数で回避できなかった理由がはっきりした。

```
Installer Type: inno
Installer Url:  https://cloud.r-project.org/bin/windows/base/old/4.6.1/R-4.6.1-win.exe
```

**`Scope` の記載が無い。** user スコープの配布そのものが存在しないので、`winget install --scope user` を試しても winget 側に入れるものがない。加えて Inno Setup 製で、昇格要求は manifest に埋まっている。引数やインストール先を変えても消せないのは、そもそも消せる場所に無いからだった。

「オプションを探す」より先に**配布物のメタデータを見る**ほうが早い。無いものは引数では作れない。

## 対処1: scoop なら非昇格で入る

scoop の main バケットに同じ 4.6.1 がある。マニフェストを取得して確認した。

```json
{ "version": "4.6.1",
  "description": "A free software environment for statistical computing and graphics." }
```

scoop は `~\scoop` 配下に展開するので管理者権限が要らない。scoop 自体の導入も非昇格で通る。

このマニフェストの `notes` には、こう書いてある。

> You'll need to type `r.exe` to run R, because in Powershell `r` runs the last command.

前節で `Get-Command R` に振り回されたのと同じ罠が、**配布元に既知の注意書きとして載っていた**。ハマる前にマニフェストを読めば済んだ。

## 対処2: UAC 待ちは consent.exe で判定できる

54分待った本体の問題はこれ。UAC ダイアログは `consent.exe` というプロセスなので、存在を見れば分かる。

```powershell
$p = @(Get-Process consent -EA SilentlyContinue)
if ($p.Count) { throw "UAC ダイアログが $($p.Count) 件出ています" }
```

CPU 使用率や成果物の不在といったヒューリスティックより直接的で、「3回試して UAC が3つ溜まった」状態をそのまま件数で取れる。

※ このクエリが非昇格の WSL から動くことは確認した（保留ゼロのとき `no pending UAC` を返す）。**ダイアログが実際に出ている状態で件数を返すところまでは未検証。**

## 検討したが今回は使わなかった手

**昇格タスクの事前登録** — 管理者権限で「最上位の特権で実行」タスクを一度登録しておき、以後は非昇格から `schtasks /run` で起動する。`schtasks /query` が非昇格で通ることは確認した。ただし**事前登録したタスクを非昇格から起動できるところまでは未検証**。初回に手動の昇格が要る点も変わらない。

**WSL 側に入れる** — `apt` に `r-base 4.3.3` はある。しかしこのマシンの `sudo` はパスワードを要求する（`sudo -n true` が失敗）。UAC を避けて sudo プロンプトで止まるだけで、非対話化の観点では改善にならない。`NOPASSWD` を設定すれば解決するが、それは別の判断が要る。

## まとめ

| 手 | 昇格 | 非対話 | 状態 |
|---|---|---|---|
| winget（既定） | 要 | ✕ UAC で停止 | 実測 |
| winget `--scope user` | — | ✕ 配布が無い | メタデータで確認 |
| scoop | 不要 | ○ | マニフェスト確認済み・未実行 |
| 昇格タスク事前登録 | 初回のみ | ○ の見込み | 未検証 |
| WSL の apt | sudo | ✕ パスワード要求 | 実測 |

入れる手段を変える（scoop）のと、待ちを即座に検出して落とす（consent.exe）のは独立に効く。前者で大半が非対話で通るようになり、後者で残りが「54分ハング」から「即座に判明」に変わる。
