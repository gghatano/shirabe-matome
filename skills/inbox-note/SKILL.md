# inbox-note — 外部で調べたことを蓄積する

`shirabe-matome` の `inbox/` にメモを1ファイル作る。ここに置いたものは、次の収集で
`material.md` に `📥 外部メモ` として取り込まれ、Claude Code のログや Discord の会話と
同じトピック列に統合される。

**ここでは公開しない。** 公開はドラフトを人が選んでからで、`inbox/` は gitignore されている。

## Step 1 — 保存先を決める

リポジトリは通常 `~/workspace/projects/shirabe-matome`。無ければユーザーに場所を聞く。

```bash
ls ~/workspace/projects/shirabe-matome/inbox/ >/dev/null 2>&1
```

## Step 2 — 中身を決める

ユーザーが渡したものによって扱いを変える。

**本文を貼ってきた場合** — そのまま使う。長くても切り詰めない（収集側が2万字で切る）。
ChatGPT の画面をコピペしたなら、`You:` `ChatGPT:` のような話者ラベルは残してよい。

**URL だけ渡された場合** — `WebFetch` で取得し、要点を自分の言葉でまとめる。
元ページの丸写しはしない。取得できなければ URL とユーザーの一言だけ記録する。

**断片的なメモの場合** — 補わない。書かれていないことを推測で足さない。

## Step 3 — ファイルを書く

パスは `inbox/<YYYY-MM-DD>-<slug>.md`。

- 日付は**今日（JST）**。ユーザーが「昨日調べた」等と言えばその日付にする
- `<slug>` は内容を表す英小文字・数字・ハイフン（例: `chatgpt-http2-priority`）
- 同名があれば末尾に `-2`, `-3` を付ける

中身はこの形にする。

```markdown
# <内容が分かるタイトル>

- 出典: <URL か、どのツールで調べたか。例: ChatGPT（web 検索あり）>
- 取得: <YYYY-MM-DD>
- 検証状況: 未検証 / 一部確認済み（確認した内容を1行で）

<本文>
```

`検証状況` は必ず書く。要約段はこの欄を見て、断定形で書くかを判断する。ユーザーが
「これは実際に動かして確かめた」と言っているなら、その旨を具体的に書く。何も言って
いなければ `未検証`。

## Step 4 — 危ないものが混ざっていないか見る

貼られた内容に次が含まれていたら、**保存する前に**ユーザーに伝えて確認を取る。

- API キー、トークン、パスワードらしき長い英数字列
- ホームディレクトリを含む絶対パス、顧客名、未公開の案件名

`inbox/` 自体は公開されないが、ここが記事の素材になる。早い段階で落としておくほうが安全。
ユーザーが「そのままでいい」と言えばそのまま保存する。

## Step 5 — 報告する

保存したパスと、何を書いたかを1〜2行で伝える。あわせて次を伝える。

- 翌朝の日次ジョブで記事ドラフトの素材になること
- `検証状況: 未検証` のものは記事でも断定形にならないこと

すぐ記事にしたい場合の手順も添える。

```bash
cd ~/workspace/projects/shirabe-matome
./daily.sh <YYYY-MM-DD>
```

## やらないこと

- `posts/` に書かない。公開は人がドラフトを選んでから
- 既にある inbox ファイルを書き換えない（追記したいと言われた場合を除く）
- 内容を「良く」しない。書き直したり補ったりせず、渡されたまま残す。誤りに気づいたら
  本文はそのままにして、`検証状況` 欄か本文末尾に「※」付きの注記として足す
