# その日の会話素材を記事ドラフトにまとめる

`drafts/{{DATE}}/material.md` を読み、その日に調べたこと・決めたことをトピックごとの
記事ドラフトにする。出力先は `drafts/{{DATE}}/` 配下。

## 何を1トピックにするか

**基準は「3ヶ月後の自分が読み返して価値があるか」**。次の日に思い出せる程度のことは書かない。

書く価値があるもの:

- 調べて分かったこと（仕様、挙動、原因）
- 詰まって解決したこと（症状 → 原因 → 対処）
- 設計上の判断とその理由（なぜその選択肢を採ったか）
- 試して駄目だったこと（同じ轍を踏まないため）

書かないもの:

- 挨拶、雑談、動作確認だけのやりとり
- 単なる作業ログ（「ファイルを3つ作った」）— 何を学んだかが無いもの
- 一般的すぎて調べ直せば済むこと

**1日に0件でも構わない**。無理に絞り出さない。逆に密度が高い日は5件以上になってもいい。

同じ話題が Claude Code と Discord の両方に出てくることがある。**ソースではなくトピックで
まとめる** — 同じ話なら1記事に統合する。

## 公開してはいけないもの

このサイトは **public な GitHub Pages** に出る。次が含まれていたら、その部分を落とすか、
落とすと記事が成立しないなら記事ごと諦める。

- APIキー、トークン、パスワード、それらしき長い英数字列
- ホームディレクトリを含む絶対パス（`/home/<user>/...` → `~/...` に書き換える）
- 未公開リポジトリ名、顧客名、案件名、個人名
- まだ公開していない成果や、公開時期が決まっていない話
- 他人の発言で、公開の同意が取れていないもの

**迷ったら落とす。** 判断がつかないものは `needs_review: true` を frontmatter に付けて、
理由を `review_note:` に書く。承認時に人が判断する。

## 書き方

- **結論を先に書く。** 経緯から書き始めない。
- コード例は **実際に動いたもの・実際に出た出力** だけ。動かしていないコードを載せない。
- 素材にある私（アシスタント）の発言は **間違っていることがある**。素材の中で実際に検証された
  ことだけを断定形で書く。検証していないものは書かないか、「未検証」と明記する。
- **`📥 外部メモ` の内容は未検証として扱う。** これは ChatGPT など別のツールで調べた結果や
  読んだ記事のメモで、この環境では何も確かめていない。断定形で書かず、「〜とされる」
  「未検証」と書くか、素材の中で実際に動かして確かめた部分だけを断定形にする。
  出典 URL が書かれているならそれを `sources` に入れる。
- 数値・エラーメッセージ・コマンドは素材からそのまま引く。記憶で補完しない。
- 見出しは `##` から。1記事 800〜2500字程度。
- 読み手は「半年後の自分」。前提の説明は要るが、初心者向けの解説は要らない。

## 出力

### 1. 記事ドラフト `drafts/{{DATE}}/<slug>.md`

`<slug>` は内容を表す英小文字とハイフン（例: `github-pages-actions`）。

```markdown
---
title: 記事タイトル（内容が分かる具体的なもの。「〜について」は避ける）
date: {{DATE}}
icon: 🚀
tags: [タグ1, タグ2]
summary: 一覧カードに出る2〜3行。何が分かるかを書く。
lead: 個別ページの見出し下に出る1行。
sources:
  - label: 参照したページ
    url: https://example.com/
---

本文
```

- `tags` は2〜3個。既存の記事と揃えると一覧で束ねやすい（`posts/` の既存記事を見る）
- `icon` は内容に合う絵文字1つ
- `sources` は素材に URL が残っているものだけ。無ければ省略

**YAML が壊れやすい点に注意する。** `title` / `summary` / `lead` の値に `:` `#` `[` `{` `"` `'`
が含まれる場合は、値全体をダブルクォートで囲む。囲まないと YAML の解釈が壊れ、公開時に
ビルドが失敗して差し戻される。

```yaml
# 壊れる — 「align-items: flex-start」のコロンがキーの区切りと解釈される
title: モバイルで横スクロールが出る原因は align-items: flex-start だった

# 正しい
title: "モバイルで横スクロールが出る原因は align-items: flex-start だった"
```

値の中にダブルクォートを含めたい場合は `\"` と書く。技術記事はコロンを含むタイトルに
なりやすいので、**迷ったら囲む**。

### 2. 一覧 `drafts/{{DATE}}/index.json`

承認時に人へ見せる一覧。

```json
{
  "date": "{{DATE}}",
  "topics": [
    {
      "slug": "github-pages-actions",
      "title": "GitHub Actions から Pages にデプロイする最小構成",
      "tags": ["GitHub Actions", "インフラ"],
      "one_line": "enablement は初回だけ権限で失敗する、という発見が中心",
      "needs_review": false,
      "review_note": ""
    }
  ]
}
```

`topics` は重要度の高い順に並べる。0件なら `"topics": []`。

## 手順

1. `drafts/{{DATE}}/material.md` を読む
2. `posts/` の既存記事を1〜2本見て、書き方とタグの粒度を合わせる
3. トピックを切り出す（統合・取捨選択はここで済ませる）
4. 各記事を `drafts/{{DATE}}/<slug>.md` に書く
5. `drafts/{{DATE}}/index.json` を書く
6. 最後に、切り出したトピック数と、公開判断が要るもの（`needs_review`）の件数を1行で報告する

`drafts/` の外には**一切書き込まない**。`posts/` への反映は人が承認したあとに別の手順で行う。

## ツールの使い方（重要）

- ファイルの作成には **Write ツール**を使う。`Bash` は許可されていないので、
  `cat > file <<EOF` のようなリダイレクトは**必ず失敗する**。
- これは非対話セッションなので、**権限を要求しても誰も応答できない**。許可されている
  範囲（`drafts/` 配下への書き込み）だけで完結させる。
- 「権限をもらえれば出力します」と報告して終わるのは**失敗**。許可されている操作だけで
  最後までやり切ること。書けないファイルがあるなら、そのファイルを諦めて残りを書き、
  最後に何を諦めたかを報告する。
