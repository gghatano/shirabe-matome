# 取りこぼしたトピックを拾う（補完パス）

`drafts/{{DATE}}/` には既に要約済みのドラフトと `index.json` がある。
同じ素材から**まだ記事になっていないトピック**を探して追加する。

## 手順

1. `drafts/{{DATE}}/index.json` を読み、既に取り上げたトピックを把握する
2. `drafts/{{DATE}}/material.md` を読み直す
3. **既存の記事が扱っていない**内容で、記事にする価値があるものを探す
4. 見つかったものを `drafts/{{DATE}}/<slug>.md` に書く
5. `index.json` の `topics` 配列に**追記**する（既存の要素は消さない・並べ替えない）

## 判断基準

`prompts/summarize.md` と同じ基準を使う。そちらを読んでから作業すること。要点だけ再掲する。

- 基準は「3ヶ月後の自分が読み返して価値があるか」
- 調べて分かったこと / 詰まって解決したこと / 設計判断とその理由 / 試して駄目だったこと
- 挨拶・雑談・単なる作業ログは書かない
- 公開できないもの（鍵・絶対パス・未公開の案件名など）は落とす。迷ったら `needs_review: true`
- `title` / `summary` / `lead` に `:` が含まれるならダブルクォートで囲む

## 重要

- **無理に絞り出さない。** 既存で十分に尽きているなら「追加なし」で終えてよい。
  薄い記事を足すくらいなら0件のほうがいい。
- 既存記事と**内容が重なるものは書かない**。角度が違うだけで同じ話なら追加しない。
- 素材で検証されていないことを断定形で書かない。

## ツールの使い方

- ファイルの作成・更新には **Write / Edit ツール**を使う。`Bash` は許可されていない。
- 非対話セッションなので**権限を要求しても誰も応答できない**。許可されている範囲
  （`drafts/` 配下）だけで完結させること。権限を求めて終わるのは失敗。

最後に、追加した件数と、追加しなかった場合はその理由を1行で報告する。
